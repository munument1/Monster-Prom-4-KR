# 한글 이름 저장·불러오기 보호 (0.1.7)

3편에서 해결했던 ASCII XML 저장 문제를 4편에서도 확인했습니다.
`CoreXmlSerializer.GenerateXMLFileStream`은 `ASCIIEncoding`을 사용하는데,
`SerializeCorePlayerData`가 이름을 일반 문자열로 쓰면 한글이 `?`로 치환됩니다.
스탯 표시 수정과 별도로 존재했던 저장 경로의 문제입니다.

3편의 `SaveNameEncoding`을 이식했습니다. 이름은 XML 문자 참조로 저장하고,
기존 XML 판독기와 암호화 형식은 유지합니다. 이름 이외의 문자열 필드는 원래 writer에
그대로 위임하며 능력치·진행 데이터는 바꾸지 않습니다.

확인한 검사:

- 원래 ASCII writer에서 한글 이름 손실을 재현했습니다.
- 한글·영문·공백·XML 특수문자·이모지 등 9가지 이름의 저장/판독 왕복을 확인했습니다.
- 원본 게임 DLL의 Encrypt/Decrypt와 UnserializeString으로 4가지 이름의 왕복을 확인했습니다.
- writer 호출을 바꾼 IL을 별도 테스트 대역에서 실행해 스택과 한글 보존을 확인했습니다.
- 게임 IL에서 ASCII writer, Name 필드 1개, 위임 대상 문자열 쓰기 18개를 확인했습니다.

이 검사는 게임을 실행하거나 장면을 로드하지 않고 수행했습니다.
실제 게임에서 저장·불러오기 화면 확인은 사용자 진행입니다.

## 이미 물음표가 된 이름

수정 DLL은 앞으로의 손상을 막습니다. `??`로 저장된 이름에는 원래 문자 정보가 없으므로
DLL만으로 임의 추측하여 복원하지 않습니다.

이번 개발 PC의 체크포인트는 사용자가 확인한 원래 이름으로 복구했습니다.
복구 전 세이브와 DLL은 로컬 `work/backups/player_name_20261026_222602/`에 보관했습니다.
체크포인트의 이름 요소 하나만 변경했고, 이름을 제외한 복호화 XML이 동일함을 확인했습니다.
수정 브리지 0.1.7도 게임 종료를 확인하고 백업 후 적용했습니다. 게임을 실행하지 않았습니다.

`scripts/RepairCheckpointName.cs`는 별도 복구 도구의 소스입니다. 원래 이름을 아는 경우에만
사용하며, 게임이 실행 중이거나 이름이 물음표만으로 구성된 단일 플레이어가 아니면 거부합니다.
수정 전에 백업과 해시를 검증하고, 이름 외 XML 동일성·재암호화·원자적 교체를 확인합니다.
개인 세이브와 백업은 공개 저장소나 패치 ZIP에 넣지 않습니다.
